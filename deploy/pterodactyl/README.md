# Ладно: Pterodactyl + существующий Nginx, Debian 13

Адрес приложения: **https://makar.frogville.fun**. Один публичный IP достаточен. Nginx на машине выбирает сайт по домену, завершает HTTPS и проксирует HTTP на allocation-порт контейнера. Порты 80/443 других сайтов, панели и Wings не меняются. Docker Compose для этой схемы не запускается.

## Единый скрипт настройки узла

Для администратора подготовлен [setup-ladno.sh](../admin/setup-ladno.sh) с этапами prepare/build/sources/proxy/check. Он загружает опубликованный комплект 0.3.0 с проверкой закреплённого SHA-256. [Краткая инструкция](../admin/ADMIN-SETUP.md). Учётные данные панели скрипту не нужны.

## Комплект для администратора

- `egg-ladno.json` — EGG формата PTDL_v2 для Pterodactyl 1.x.
- `Dockerfile`, `entrypoint.sh` — собственный образ Debian 13 с готовым сервером, без скачивания приватного репозитория из контейнера.
- `../admin/build-image.sh` — сборка образа на узле Wings.
- `../admin/configure-nginx.sh` — генерация и необязательное применение отдельного сайта Nginx.

Исходники должны быть переданы администратору архивом или получены из приватного репозитория его собственным разрешённым способом. Токен GitHub не нужен ни EGG, ни работающему контейнеру.

## 1. Собрать образ на машине Wings

Docker уже должен быть настроен администратором узла. Из корня полученных исходников:

```bash
bash deploy/admin/build-image.sh
```

Образ называется `ladno-backend:pterodactyl`. Импортировать EGG через административную панель → Nests → Import Egg. Выбрать этот образ в созданном сервере. Если панель/политика узла требует скачивание из registry, администратор должен загрузить образ в свой доступный registry и заменить имя образа в EGG/Startup; опубликованного образа по этому имени в Docker Hub нет. На нескольких узлах образ должен быть доступен каждому из них. Вложенный Docker внутри сервера не нужен.

Создать сервер с этим EGG: память от 768 МБ (рекомендуется 1 ГБ), CPU 100%, диск от 15 ГБ. Данные занимают журнал, вложения и историю; лимит вложений не заменяет дисковый лимит панели. Не включать доступ к Docker socket или привилегированный режим.

## 2. Выделить порт

Создать свободный TCP allocation, например **18080**. Это пример: администратор выбирает свободный порт и IP привязки узла. Приложение слушает `0.0.0.0:SERVER_PORT` внутри контейнера. Постоянные данные только в `/home/container/data`; обновление/пересборка образа их не удаляет.

После запуска в консоли появится `Ladno backend listening`. На самой машине проверить:

```bash
curl --fail http://127.0.0.1:18080/health
```

Если allocation привязан к публичному IP, а не loopback, использовать этот IP вместо `127.0.0.1`. Nginx должен обращаться к тому адресу, по которому порт доступен с хоста.

**HTTP allocation нельзя оставлять доступным из интернета:** по нему передаются токены и данные. Предпочтительна локальная привязка, если её допускает конфигурация Wings. Иначе администратор ограничивает внешний доступ к этому порту в действующем firewall Docker/хоста, сохраняя доступ Nginx с машины. Обычное правило UFW само по себе может не закрыть опубликованный Docker-порт. Прочие allocation, SSH, панель и Wings трогать не нужно. После настройки проверить с другой машины, что прямой HTTP-порт недоступен, а HTTPS-домен доступен.

## 3. Настроить Nginx

DNS A домена должен указывать на публичный IP машины. AAAA не добавлять, если IPv6 не настроен. Сертификат обязан включать `makar.frogville.fun`; ключ и полная цепочка находятся только на машине Nginx.

Сначала создать файл для проверки администратором:

```bash
bash deploy/admin/configure-nginx.sh \
  --port 18080 --upstream-host 127.0.0.1 \
  --cert /etc/letsencrypt/live/makar.frogville.fun/fullchain.pem \
  --key /etc/letsencrypt/live/makar.frogville.fun/privkey.pem \
  --output /tmp/ladno-nginx.conf
```

Пути и IP заменить на реальные. Если сайт этого домена уже существует, объединить настройки вручную; нельзя создавать второй `server_name makar.frogville.fun`.

Для явного применения нового сайта на Debian можно выполнить команду с `sudo` и `--apply`, указав **другое свободное имя выходного файла**. Скрипт откажется перезаписывать существующий сайт, проверит `/health`, установит только `ladno-makar.conf`, выполнит `nginx -t`, а затем `systemctl reload nginx`. При ошибке теста новый файл удаляется, работающие сайты не перезагружаются. Проверить после применения:

```bash
curl --fail https://makar.frogville.fun/health
```

Скрипт не выдаёт сертификат, не перенастраивает ACME, firewall и 80-й порт. Обновление сертификата выполняется существующим механизмом администратора с последующим reload Nginx.

## 4. Подключить телефон и компьютер

В приватной консоли Pterodactyl выполнить:

```text
invite
```

Появится один код на 10 минут. В новой клиентской сборке: Настройки → Синхронизация с сервером → `https://makar.frogville.fun` → имя устройства → код. Для каждого устройства выдаётся отдельный код. Старые установщики **0.2.1 этого подключения не поддерживают**.

Консоль содержит секретные одноразовые коды: доступ к ней — только у владельца и администратора. Приглашение нельзя использовать повторно. В постоянной базе сервер хранит SHA-256 токенов; само приложение хранит токен в защищённом хранилище ОС. Повторное подключение существующего device ID по новому коду заменяет прежний токен.

```text
help
 devices
 revoke UUID_УСТРОЙСТВА
 stop
```

`devices` показывает ID, имя и состояние. `revoke` блокирует дальнейший обмен этого устройства, не удаляя локальные записи с него. `stop` корректно завершает сервер; кнопка Stop в EGG использует эту команду.

## Копии и восстановление

Перед серверной копией остановить сервер через панель и дождаться состояния Offline. Сохранить **весь** каталог `/home/container/data`, включая SQLite, её файлы журнала при наличии и каталог вложений. Копирование одной работающей SQLite не является полной согласованной копией. Использовать штатные резервные копии панели при остановленном сервере. Дополнительно сохранять клиентские `.ladno`-архивы. Копии содержат тексты/файлы; доступ к ним ограничить.

Восстанавливать в отдельный остановленный сервер/каталог, сохранив исходную копию. После отката к старому серверному архиву перед запуском администратор должен выполнить `ladno-server recover` **при остановленном основном процессе**, с `DATA_DIR` на восстановленный каталог. Это меняет ID сервера, очищает подтверждения и отзывает токены, но сохраняет операции и файлы. Затем запустить и выдать устройствам новые приглашения. Клиенты заново выгрузят известные им операции; иначе подтверждённые после даты копии изменения могут не передаться повторно. Команда `recover` намеренно отсутствует в живой консоли — не выполнять её параллельно работающему серверу.

## Что проверено и что ещё требуется

Автотесты проверяют реальный HTTPS, двух клиентов, заметки/задачи/вложения, конфликты, одноразовые коды, отзыв токена и сохранность при перезапуске. CI дополнительно собирает Compose-образ и образ Pterodactyl, проверяет allocation, stdin-команды и постоянный каталог. Это не заменяет импорт EGG и сетевую проверку на настоящем узле администратора. Docker-образ, домен и контейнер на вашей машине автоматически не разворачиваются.

Официальные требования к образам: https://docs.pterodactyl.io/v1/guides/egg-creation/creating-custom-image .
