# Ладно

Личное приложение на русском для Android, Windows 10/11 x64 и Fedora. Локальные заметки и задачи работают без интернета; обмен идёт через личный бэкенд. Текущая разработка: **0.3.0-dev.2**, переход на Docker/Pterodactyl.

## Сервер для makar.frogville.fun

Целевая схема: приложение → `https://makar.frogville.fun` → существующий Nginx на Debian 13 → выделенный HTTP-порт контейнера Pterodactyl. Один публичный IP; порт 443 и сертификат обслуживает уже работающий Nginx. Сам контейнер не получает TLS-ключ, Docker socket или доступ к другим серверам.

[Комплект и инструкция для администратора](deploy/pterodactyl/README.md): EGG, собственный образ Debian 13, скрипт сборки и настройка Nginx. Внутри Pterodactyl Docker Compose не запускается. [Docker Compose](compose.yaml) оставлен отдельным вариантом для самостоятельного сервера/CI с собственным прокси, когда 443 свободен.

Подключение приложения: Настройки → Синхронизация с сервером → адрес домена → имя устройства → одноразовый код из приватной консоли панели (`invite`). Для каждого устройства отдельный код на 10 минут. Токен хранится в защищённом хранилище ОС, сервер хранит его SHA-256. Потерянное устройство отзывается командой `revoke UUID`.

## Возможности рабочей версии

- Заметки, Markdown, папки, поиск, история редакций, корзина и темы.
- Задачи, проекты, подзадачи, приоритеты, теги, Сегодня/Предстоящие, календарь и повторные задачи с защитой от дублей.
- Общий причинный журнал: локальное сохранение, передача операций через сервер, явные конфликтующие варианты без скрытого уничтожения текста.
- Вложения до 100 МБ, SHA-256, передача блоками и докачка. Полные `.ladno`-копии содержат журнал и файлы, но не токены и настройки подключения.
- Напоминания включаются отдельно на устройстве; Android/Windows используют планировщик ОС, Linux — таймеры при работающем приложении. Доставка на реальном устройстве требует проверки.

Телефон обменивается данными при открытом приложении. ПК — пока процесс работает, включая свёрнутое окно. Изменения на другом устройстве поступают после обмена. Сервер видит содержимое записей: это собственный доверенный бэкенд, не сквозное шифрование. Локальная база и резервные копии не зашифрованы полностью.

При первом подключении существующая локальная история выгружается на сервер, затем принимается серверная. Переключение между серверами объединяет их доступную историю; не подключайте чужой сервер. После восстановления клиентской копии требуется новое приглашение. Откат серверного архива требует процедуры `recover`, описанной администратору.

## Установщики

[Опубликованная версия 0.2.1](https://github.com/sssolyarka/ladno/releases/tag/v0.2.1) относится к прежнему этапу и **не поддерживает Docker-бэкенд или задачи**. Новая серверная версия находится в рабочей ветке; её установщики не объявлены готовыми.

## Сборка клиента

Проверенная среда: Flutter 3.47.9 stable / Dart 3.13.7. Общий чистый Dart-пакет находится в `packages/ladno_sync`; он нужен и клиенту, и бэкенду.

```bash
flutter pub get --enforce-lockfile
dart analyze lib test
flutter test --no-pub
```

Fedora: нужны clang, cmake, ninja-build, pkgconf-pkg-config, gtk3-devel, libstdc++-devel, sqlite-devel и libsecret-devel; хранилищу токена — Secret Service (разблокированный GNOME Keyring или совместимый кошелёк). `flutter build linux --release --no-pub`.

Windows: Visual Studio 2022 с Desktop development with C++, Windows SDK и CMake; `flutter build windows --release --no-pub`.

Android: Android SDK/Java по настройке Flutter, `flutter build apk --debug --no-pub`. Выпуск требует прежнего постоянного ключа; GitHub Secrets не входят в исходники. SDK 36, разрешения уведомлений запрашиваются при их включении. Разрешение камеры для нового серверного подключения не требуется.

## Сборка сервера отдельно от Flutter

```bash
cd server
dart pub get --enforce-lockfile
dart analyze
dart compile exe bin/server.dart -o ladno-server
```

Сервер использует SQLite и тот же пакет журнала. Без Docker для запуска нужна системная `libsqlite3.so` (на Debian — пакет `libsqlite3-dev`). Клиентская база и серверная база раздельны; у каждого экземпляра свой постоянный origin. Один контейнер обслуживает одно личное пространство, не несколько независимых пользователей.

[Архитектура](docs/ARCHITECTURE.md), [состояние задач/повторов](docs/STAGE3.md), [проверки](docs/VERIFICATION.md). Старые материалы второго этапа сохранены как история, но LAN/QR-сервис больше не используется рабочим интерфейсом.
