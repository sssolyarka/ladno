# Второй этап — версия 0.2.0

## Реализовано

Привязка по временному QR или полному скопированному адресу, сравнение шестизначного кода и подтверждение с двух сторон. Отдельный временный TLS-сервис привязки не имеет доступа к заметкам. Сертификат и ключ генерируются на устройстве готовой библиотекой basic_utils/PointyCastle; ключ и доверие сохраняются через flutter_secure_storage. Нет ключа разработчика и открытого файлового обхода при отказе кошелька ОС.

Основной транспорт TLS 1.3 проверяет сертификат клиента и точный отпечаток доверенного устройства. mDNS/DNS-SD обновляет адрес известных устройств, но не устанавливает доверие. При ошибке обнаружения остаётся QR/скопированный адрес. Имена и адреса из сети не заменяют проверку сертификата.

Контроллер подключён к редактору и жизненному циклу приложения: обмен после сохранения, при запуске/возвращении и повтор каждые 30 секунд, ручной обмен, отмена, остановка в фоне и отзыв доверия. Заметки сохраняются независимо от доступности второго устройства.

Журнал и отображение заметки фиксируются одной транзакцией; подтверждение выдаётся после commit. Причинные родители, логические часы, повтор без дублей, отметки удаления, возврат старого устройства и конфликтующие варианты сохраняются. Отметки удаления и журнал пока не очищаются автоматически. Редактор передаёт исходную версию; поздняя редакция не поглощается старым экраном объединения. Для удаления против редактирования по умолчанию отображается корзина, текст остаётся доступен для объединения. Остальные поля отображаются детерминированно, разные варианты остаются в модели и диалоге. Есть объединение папок, включая удалённые.

Вложения до 100 МБ на файл: локальный снимок, SHA-256, ограниченные блоки, продолжение и атомарная публикация. Текст передаётся первым, недоступные файлы показываются отдельно. Есть добавление/удаление связи с файлом, предпросмотр изображений и экспорт. Файлы из прежних операций сохраняются для истории и копий.

Полный `.ladno` — ZIP без сжатия до 256 МБ: JSON-снимок до 50 МБ и файлы по хешам. Проверяются состав, пути, размеры, CRC и SHA-256; символические ссылки и сжатые записи не принимаются. Импорт JSON v1/v2 без вложений поддерживается. Восстановление останавливает сеть, создаёт новый origin и требует повторной привязки. Секреты, доверие, настройки и подтверждения доставки не экспортируются.

## Проверки

Полный прогон 88 тестов прошёл на GitHub, дополнительная проверка удалённого удаления открытой заметки прошла локально. Release-сборка Linux выполнена на Fedora. Окончательный результат смотрите в Actions для конкретного commit. Автоматические тесты используют временные базы/ключи и реальные локальные HTTPS-соединения. Два независимых контроллера проходят привязку, двусторонний обмен, передачу файла, повтор, перезапуск и отзыв доверия.

Это не проверка реального телефона: камера Android, системные кошельки на Windows/Android, диалоги файлов, разрешения сети и реальный multicast на каждой ОС требуют пользовательской проверки. Сборка Windows Server не заменяет Windows 10. Результаты сборок и готовые установщики — в GitHub Actions/Releases.

## Ограничения

Телефон синхронизируется при открытом приложении; фоновой службы нет. Только IPv4. Поиск зависит от ОС, Avahi/mDNS и настроек сети. Если сменился адрес и multicast закрыт, нужна повторная привязка. Нет сетевого облака, учётных записей, автообновления, PIN и полного шифрования базы/архива. Защищённое хранилище защищает ключи, а не тексты заметок на диске. Отдельная авторизация владельца телефона/ПК не заменяется привязкой.

Файловый архив ограничен 256 МБ и требует наличия всех файлов журнала: при незавершённой докачке полная копия отклоняется с объяснением. Журнал и старые файлы растут; автоматическая сборка мусора не включена. Markdown-редактор остаётся текстовым; внешние изображения не загружаются.

## Сборка

Flutter 3.47.9, Dart 3.13.7, зависимости зафиксированы в pubspec.lock. Для тестов нужен OpenSSL. Linux-сборке нужен libsecret-devel (Ubuntu: libsecret-1-dev), для работы ключей — служба Secret Service. CI использует закреплённые версии инструментов и Actions. Ключ подписи Android уже хранится отдельно в GitHub Secrets и не используется синхронизацией.
