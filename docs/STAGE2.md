# Второй этап: состояние разработки

Проверено на Fedora 10 ноября 2026 года: 77 тестов успешно, `dart analyze lib test` без замечаний после исправления оформления.

## Реализовано

- Постоянный идентификатор устройства, журнал операций SQLite, причинные связи и логические часы.
- Идемпотентное получение и подтверждение только после записи на диск, повтор после потери подтверждения.
- Сохранение параллельных вариантов полей, явное объединение через новую операцию, удаление против редактирования.
- Пакеты с ограничением размера и числа операций, проверка версии протокола и структуры входных данных.
- HTTPS TLS 1.3 с сертификатами обоих устройств и проверкой точного отпечатка. Сервер отказывает запросам без доверенного сертификата, включая уже открытое соединение после отзыва доверия.
- Двусторонний обмен через один слушающий сервер; отмена и ограничение времени запросов.
- Вложения по SHA-256: снимок при импорте, частичная передача, продолжение, проверка полного хеша, атомарная публикация. Отсутствующие файлы возвращаются отдельно от успешного обмена текстом.

- Журнал подключён к пользовательской базе: операция и отображение заметки фиксируются одной транзакцией; ошибка отображения откатывает и журнал.
- Миграция v1→v2 с копией закрытой базы, сравнением SHA-256 и SQLite integrity_check. Существующие заметки, метаданные и история сохраняются.
- Редактор передаёт исходные причинные версии и меняет только отредактированные поля. Очередь его снимков не создаёт ложных конфликтов. Чужие изменения не подменяют исходную версию открытого редактора.
- Значок конфликта, сравнение вариантов и ручное объединение в интерфейсе, включая удаление против редактирования. Новые изменения во время диалога сохраняются как конфликт.
- Логическая резервная копия v2 с полным журналом и конфликтами, импорт v1; восстановление создаёт новый локальный origin и инвалидирует прежние редакторские снимки. Ключи, настройки и подтверждения доставки не экспортируются.

Модули находятся в `lib/sync`, тесты — в `test/sync`. Транспорт пока не запускается из интерфейса: подключение и автоматический обмен не готовы. Выпуск v0.1.0 не содержит этих изменений.

## Остаётся до готового второго этапа

1. Подключить сетевую сессию к жизненному циклу приложения и общей базе, обновлять интерфейс после обмена.
2. Генерация и хранение ключей в системном защищённом хранилище Windows/Android/Linux. Сейчас идентификаторы TLS передаются модулю извне; тестовые ключи временные, создаются OpenSSL и удаляются.
3. Привязка устройств через QR и сравнение кода с подтверждением на обоих экранах, обнаружение в локальной сети и ручной адрес при недоступном multicast.
4. Отдельные статусы соединения и синхронизации, список доверенных устройств и отзыв доверия в интерфейсе.
5. Интерфейс вложений и файловый резервный архив. Текущая JSON-копия содержит конфликты, но при наличии вложений намеренно отклоняется; молчаливого неполного экспорта нет. Отдельный экран объединения конфликтов папок.
6. Реальные проверки Fedora ↔ Windows 10 ↔ Android. Локальные HTTPS-тесты на Fedora не заменяют эти проверки.

Автоматическая проверка ветки: `.github/workflows/checks.yml` (Linux, OpenSSL, закреплённые зависимости; без ключей выпуска).

## Продолжение на Windows

Получить ветку `codex/stage-2-sync` этого репозитория. Нужны Flutter 3.47.9 и OpenSSL в PATH для сетевых тестов. Выполнить `flutter pub get --enforce-lockfile`, `dart analyze lib test`, `flutter test --no-pub`.

Не копировать тестовые ключи и идентификатор устройства между компьютерами. Постоянный ключ подписи Android хранится отдельно в GitHub Secrets и не используется синхронизацией.
